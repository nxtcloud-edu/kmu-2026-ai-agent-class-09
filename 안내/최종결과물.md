# 최종 결과물

## 만들 것

내가 반복하는 일을 맡을 에이전트를 만든다. 에이전트의 수와 구성은 각자 정한다. 에이전트 하나로 해도 되고, 여러 에이전트나 서브에이전트로 나눠도 된다. 만든 것은 매일 스스로 돌고, 내가 받는 곳으로 결과를 보내고, 결정이 필요하면 나에게 묻는다. 그것을 2주(13~14주차) 동안 실제로 쓰고 기록한다.

무엇을 만들지 정하기 어려우면 [예시_시나리오.md](예시_시나리오.md)를 본다.

## 제출물

| 제출물 | 내용 | 레포의 위치 | 마감 |
|---|---|---|---|
| 계획서 | 맡길 일, 구성, 흐름, 검증, 일정 | `계획서.md` | 10주차 수업 끝(1~5번), 11주차 전(6~10번) |
| 도는 에이전트 | 내가 고른 도구에서 도는 에이전트(여럿이어도 된다) | 15주차에 시연 | 12주차 끝 |
| 구성 | 에이전트, 스킬, 커스텀 도구, 스케줄, 워크플로우, 가드레일 | `구성/` | 15주차 |
| 주차 기록 | 주차마다 꼭 남길 항목 | `기록/주차/` | 매주 수업 끝 |
| 운영 기록 | 사용 일지, 변경 기록 | `기록/일지/`, `기록/변경.md` | 13~14주차에 매일 |
| 발표 | 시연, 운영 기록으로 본 결과, 고친 것, 회고 | `발표/` | 15주차 |

## 도구 고르기

Kiro Crew를 쓰지 않아도 된다. 익숙한 도구가 있으면 그 도구로 만들어도 되고, 여러 도구와 AI를 엮어도 된다. 조건은 다섯 가지다.

- 10주차 계획서에 쓰는 도구와 고른 까닭을 쓴다.
- 12주차부터는 도구를 바꾸지 않는다.
- Kiro Crew가 아닌 도구의 사용법은 스스로 해결한다. 강사는 설계, 범위, 기록을 함께 본다.
- 유료 도구나 API의 비용은 각자 낸다.
- 어떤 도구를 써도 기록은 이 레포에 같은 형식으로 남긴다.

## 꼭 들어갈 기능

도구가 아니라 기능으로 본다. Kiro Crew로 하면 오른쪽 칸처럼 채운다.

| 기능 | 기준 | Kiro Crew로 하면 |
|---|---|---|
| 재사용하는 절차 | 1개 이상. 같은 절차를 파일로 남겨 반복해서 부른다 | 스킬 |
| 근거 자료 | 내 일에 쓰는 실제 자료를 찾아 답의 근거로 쓴다 | 지식 (RAG) |
| 직접 쓴 코드 | 1개 이상. 외부 자료를 가져오거나, 계산하거나, 검사한다. 설정만 한 것은 인정하지 않는다 | 스킬의 `scripts/` |
| 정해진 때의 자동 실행 | 매일 1회. 사람이 시작하지 않아도 돈다 | 스케줄 |
| 사람의 결정 | 1곳 이상. 멈추고 나에게 묻는다 | Slack 선택 버튼, 대시보드 |
| 막는 규칙 | 1개 이상. 하면 안 되는 동작을 실행 전에 막는다 | 가드레일 |
| 결과를 받는 곳 | 결과가 나에게 온다. Slack이 아니어도 된다. 예: 메일, 메신저, 대시보드, 파일 | Slack DM |

## 사람이 해도 되는 단계

모든 단계를 자동으로 만들지 않아도 된다. 예를 들어 자료 모으기는 Aside 같은 AI 브라우저로 하고, 그 결과를 내가 복사해서 파일로 저장해도 된다. 그다음 단계를 에이전트가 맡으면 된다.

사람이 하는 단계는 두 곳에 적는다.

- 계획서의 처리 흐름: 그 단계의 담당을 "사람"으로 쓰고, 쓰는 도구를 함께 쓴다.
- 사용 일지: 그날 손으로 한 일과 걸린 시간을 쓴다.
