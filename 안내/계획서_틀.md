# 계획서 틀과 예

`계획서.md`의 모든 칸을 채운다. 이 파일은 각 칸에 무엇을 쓰는지와 예를 보여 준다. 예는 "취업 공고 점검"이다.

## 1. 맡길 일

| 칸 | 쓸 것 | 예 |
|---|---|---|
| 서비스 이름 | 한 줄 | 아침 공고 브리핑 |
| 반복하는 일 | 누가, 무엇을, 얼마나 자주 하는가 | 나는 매일 아침 채용 사이트 3곳을 본다 |
| 지금 하는 방법 | 단계와 걸리는 시간 | 사이트 3곳 검색 → 내 조건과 비교 → 메모. 하루 30분 |
| 에이전트에게 맡길 부분 | 단계 번호 | 검색, 비교, 메모 정리 |
| 내가 계속 할 부분 | 단계 번호 | 지원 여부 결정 |
| 완료 조건 | 한 번 실행하면 무엇이 나와야 끝인가 | 새 공고 목록과 공고마다 맞는 정도·근거가 Slack에 온다 |

## 2. 하루 사용 장면

시간 순서로 쓴다. 언제 무엇이 시작되는지, 결과를 받는 곳에 무엇이 오는지, 내가 무엇을 누르는지 쓴다.

예: 08:00 스케줄 시작 → 08:05 Slack(또는 메일)에 공고 5건 → 지원할 2건 승인 → 승인한 2건만 지원 준비 메모가 만들어진다

## 3. 구성요소

기능마다 무엇으로 채우는지 쓴다. 도구는 자유다. 기준은 [최종결과물.md](최종결과물.md)의 "꼭 들어갈 기능"에 있다.

| 칸 | 쓸 것 | Kiro Crew로 하면 | 배운 주차 |
|---|---|---|---|
| 쓰는 도구와 고른 까닭 | 도구 이름, 그 도구를 고른 까닭 | Kiro Crew | |
| 에이전트 | 역할과 지시. 여럿이면 에이전트마다 쓴다 | 에이전트 | 2 |
| 재사용하는 절차 | 이름, 절차, 함께 둘 코드 | 스킬 | 3 |
| 근거 자료 | 자료 목록과 출처 | 지식 | 4 |
| 직접 쓴 코드 | 무엇을 하는가, 입력, 출력 | 스킬의 `scripts/` | 3 |
| 정해진 때의 자동 실행 | 실행 시각, 여러 단계면 그 단계 | 스케줄, 동적 워크플로우 | 6·9 |
| 사람의 결정 | 어디서 무엇을 묻는가, 왜 자동으로 하면 안 되는가 | Slack 선택 버튼, 대시보드 | 6~7 |
| 막는 규칙 | 막을 동작 | 가드레일 | 6~7 |
| 결과를 받는 곳 | 받는 것, 보내는 것 | Slack DM | 9 |

"왜 자동으로 하면 안 되는가"는 세 기준 가운데 하나 이상으로 쓴다: 되돌리기 어렵다, 책임이 따른다, 기준이 모호하다.

## 4. 처리 흐름

입력부터 출력까지 단계를 쓴다. 단계마다 담당을 정한다: 코드, 에이전트, 사람. 모든 단계를 자동으로 만들지 않아도 된다. 사람이 하는 단계에는 쓰는 도구를 함께 쓴다(예: Aside로 공고를 보고 결과를 `inbox/`에 저장한다).

| 단계 | 하는 일 | 담당 | 입력 → 출력 |
|---|---|---|---|
| 1 | 공고 수집 | 코드 | 검색어 → 공고 목록 JSON |
| 2 | 내 조건과 비교 | 에이전트 | 공고 목록, 이력서(지식) → 맞는 정도와 근거 |
| 3 | 지원 여부 결정 | 사람 | 비교 결과 → 승인한 공고 |

## 5. 검증 방법

| 칸 | 쓸 것 | 예 |
|---|---|---|
| 형식 검사 | 코드로 확인할 것 | 공고마다 회사·마감일·링크가 있는가 |
| 내용 검사 | 원본과 대조할 것 | 마감일이 공고 원문과 같은가 |
| 틀렸을 때 | 누가 알게 되고 무엇을 하는가 | 검사 실패를 Slack에 알리고 그 공고는 빼고 보낸다 |

## 6. 이번에 만들지 않는 것

자른 기능을 목록으로 쓴다. 자른 까닭을 함께 쓴다.

## 7. 일정과 확인 지점

| 시점 | 끝나 있어야 할 것 |
|---|---|
| 11주차 끝 | 스킬과 커스텀 도구가 손으로 실행해서 한 번 돈다 |
| 12주차 끝 | 정해진 때의 자동 실행으로 처음부터 끝까지 한 번 돌고, 결과를 받고, 결정을 한 번 한다 |
| 13주차 시작 | 매일 사용을 시작한다 |
| 14주차 끝 | 기준 수치를 채우고 발표 자료 초안을 만든다 |

## 8. 사용 계획 (13~14주차)

| 칸 | 쓸 것 |
